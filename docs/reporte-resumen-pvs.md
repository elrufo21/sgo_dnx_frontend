# Resumen PVS por cliente

En **Resumen PVS**, opción independiente del menú disponible con el permiso `VENTAS.VER`, se busca un cliente por código, DNI o nombre y se consulta un intervalo de fechas. Se incluyen clientes activos e inactivos. Al abrir, el intervalo abarca el mes actual; Buscar ejecuta la consulta. El detalle muestra fecha de pago, transacción, código, cliente, PV, SV e importe; la última fila muestra cantidad y totales del resultado completo, no solo de la página visible. Una consulta vacía o fallida borra los resultados anteriores.

La API `GET /api/v1/PvsReport?clienteId=...&fechaInicio=yyyy-MM-dd&fechaFin=yyyy-MM-dd` requiere el mismo permiso y valida cliente y fechas. Reproduce las reglas de `uspResumenPVS`: notas `CANCELADO` del cliente por `NotaFechaPago`, con al menos un detalle, PV y SV sumados por nota e importe `NotaPagar`, ordenadas por ID descendente. Cada valor monetario o de puntos se presenta con dos decimales y los totales suman esos valores. La consulta devuelve números y no utiliza `NOLOCK`. El [SQL de referencia de solo lectura](../../sgo_dnx_backend/scripts/sql/20261102_consulta_resumen_pvs.sql) no instala ni modifica objetos.

Para usar el módulo se deben ejecutar o publicar las versiones actualizadas de la API y el frontend. El selector muestra inicialmente hasta 30 clientes y permite buscar por código, DNI o nombre desde el primer carácter. No modifica clientes, notas ni fechas. La consulta requiere las tablas y columnas del procedimiento heredado; se debe verificar el esquema de cada base antes de su publicación.

La API requiere el token de la sesión en la cabecera `Authorization`; abrir su URL directamente en la barra del navegador no envía ese token y devuelve HTTP 401. El reporte web adjunta la sesión y distingue errores de conexión, sesión y permisos. Si no hay resultados, la pantalla indica que solo se incluyen notas con estado `CANCELADO` y fecha de pago en el período; las notas `PENDIENTE` no forman parte del resumen heredado.
